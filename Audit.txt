🏛️ دكاني — المخطط المعماري النهائي لمحرك الأوديت والتزامن (الإصدار 1.0)
📜 الديباجة: فلسفة "المرآة المزدوجة للأوديت"
هذه الوثيقة هي المرجع المعماري الوحيد لمحرك الأوديت والتزامن في منصة "دكاني". تدمج جميع التحسينات والمراجعات السابقة في نسخة واحدة نهائية، خالية من التكاليف المستترة، وقابلة للتنفيذ الفوري.

الفكرة الجوهرية: كل حدث في المنصة (تعديل سعر، تغيير مخزون، طلب جديد، تعديل إعدادات) هو كائن موحد يمر عبر أنبوب واحد (Single Pipeline)، مع تطبيق المرآة المزدوجة لعرض التغييرات فوراً في المتصفح (0ms)، مع الحفاظ على تكلفة تشغيلية صفرية مطلقة.

1️⃣ المبادئ الهندسية الحاكمة (Core Principles)
المبدأ	الوصف
Single Event Pipeline	كل حدث يُعامل كـ AuditEvent ببنية موحدة ويمر عبر نفس الـ Capture Worker.
CQRS & Optimistic UI	عمليات القراءة من IndexedDB (0ms)، والكتابة تُرسل في الخلفية مع تحديث تفاؤلي للواجهة.
Dual Replica for Every Change	كل حدث يُنسخ محلياً في IndexedDB فوراً، ويُرسل إلى D1، ثم يُنقل إلى B2 للأرشيف.
Zero-Cost Resilience	معالجة جميع الثغرات (SSE Exhaustion، OOM، Lock Starvation، Range Requests، Duplicate Events) مع الحفاظ على التكلفة الصفرية.
Stateless Sync	لا تُستخدم WebSockets أو Durable Objects المفتوحة باستمرار. الاعتماد على SSE On-Demand + BroadcastChannel + Polling Fallback.
Server Time Canonicalization	توقيت الأحداث يُحدد بواسطة Worker (server_received_at) مع نافذة قبول ±5 دقائق للأحداث المتأخرة.

3️⃣ التدفق المعماري الكامل (End-to-End Data Flow)
3.1. الالتقاط الفوري مع Optimistic UI (الزمن: 0ms للواجهة، < 10ms للخادم)
التدفق:

التاجر يعدل قيمة (سعر/مخزون) في Dashboard.

Optimistic Update (0ms):

OptimisticUpdateManager يطبق التغيير في IndexedDB و UI فوراً.

يُضاف الحدث إلى PendingMutationStack مع sequence_id محلي.

الإرسال في الخلفية:

يُرسل AuditEvent إلى Capture Worker عبر fetch() مع keepalive: true (بدلاً من sendBeacon للحصول على HTTP Status Code).

لا ينتظر العميل الرد (غير متزامن).

معالجة الخادم (Capture Worker):

يتحقق من idempotency_key عبر D1 (INSERT OR IGNORE).

يكتب الحدث في D1 (الجدول الشهري المُولَّد ديناميكياً) مع server_received_at.

إذا كان الفرق بين client_created_at و server_received_at > ±5 دقائق، يضع علامة is_backfilled: true.

يُحدّث Redis last_ts للمتجر.

يُرسل نبضة عبر SSE (إذا كان التاجر متصلاً).

الرد والتحقق:

إذا نجحت العملية: يُحدث IndexedDB الحالة إلى 'synced' ويزيل الحدث من الـ Stack.

إذا فشلت (4xx/5xx): يقوم OptimisticUpdateManager بـ Rollback للحدث الفاشل فقط، ثم يعيد تطبيق (Replay) الأحداث اللاحقة في الـ Stack (مع أخذ Snapshot قبل الـ Replay) للحفاظ على تناسق UI.

3.2. البث الحي والتزامن (Pulse & Sync Engine)
المبدأ: التزامن صفر التكلفة مع فتح الاتصال عند الطلب فقط.

Cross-Tab Sync (نفس الجهاز):

استخدام BroadcastChannel باسم dokany_audit_${storeId}.

Fallback للمتصفحات القديمة: window.addEventListener('storage') مع localStorage.

Cross-Device Sync (بين الأجهزة):

Stateless SSE عبر Cloudflare Worker يُفتح عند الطلب (عند دخول التاجر شاشة الطلبات).

يُغلق الاتصال تلقائياً بعد 30 ثانية من الخمول.

مفتاح الاتصال المركب: استخدام storeId:tabId كـ Composite Key لمنع تعارض التبويبات المتعددة.

حد أقصى 5 اتصالات SSE لكل storeId، مع رفض أي اتصال إضافي بـ 429 Too Many Requests.

Polling Fallback: إذا تعذر فتح SSE، يتحول العميل إلى Polling مع Exponential Backoff (1s → 2s → 5s → 10s كحد أقصى) مع Jitter عشوائي.

Master Tab Pattern:

التبويب الرئيسي (الأول) يستقبل SSE ويكتب في IndexedDB.

يبث التحديثات للتبويبات الأخرى عبر BroadcastChannel.

Master Election Protocol: Heartbeat كل 1000ms، Timeout 2500ms، مع استخدام navigator.locks مع AbortSignal.timeout(500ms) لانتخاب تبويب بديل فوراً.

3.3. التجميع والتحويل (Raw Aggregation & Heavy Rollup)
⚠️ تحذير: تم إلغاء تشغيل DuckDB-WASM داخل Cloudflare Workers لتجنب تجاوز حد الذاكرة 128MB.

الجدولة: عبر Upstash QStash (مجاني، 10k طلب/شهر).

كل ساعة: Worker التجميع يقرأ الأحداث الجديدة من D1، يكتبها كـ JSON Lines في B2 (/raw/.../chunk_{HH}.json).

كل ساعة (تحويل فوري): Worker يقوم بتحويل ملف JSON الساعي إلى Parquet باستخدام مكتبة Parquet خفيفة (مثل @dsnp/parquetjs أو parquet-wasm) مع ضغط ZSTD، ويرفعه إلى B2 (/parquet/.../chunk_{HH}.parquet). (حجم < 2MB، ويتم تقطيع الدفعات إلى 1000 حدث كحد أقصى لضمان المعالجة خلال 5 ثوانٍ).

يومياً (Daily Compaction): في منتصف الليل، تُدمج الملفات الساعية الـ 24 في ملف يومي واحد (events.parquet) وحذف الملفات الساعية لتقليل عدد الملفات من 720 إلى 30 شهرياً.

أسبوعياً/شهرياً: تُدمج الملفات اليومية في ملفات أسبوعية وشهرية.

شهرياً (Purge): في أول الشهر، يُحذف الجدول القديم من D1 بعد التأكد من وجود monthly_summary.parquet في B2.

توزيع حمل Compaction: استخدام QStash Fan-out لتقسيم المتاجر على دفعات (Batches) وتوزيع المعالجة على مدار 3 ساعات (2:00 AM → 5:00 AM UTC) لتجنب Worker Timeout.

3.4. التحليلات والاستعلامات (Client-Side Analytics)
الإحصائيات السريعة (Daily Overview): تُحسَب من IndexedDB باستخدام reduce() على مصفوفة الأحداث (زمن < 50ms، بدون DuckDB).

التقارير المتقدمة (Advanced Analytics):

Pre-fetching: Service Worker يقوم بتحميل JSON Rollups لآخر 7 أيام في الخلفية (من B2 عبر Cloudflare CDN) وتخزينها في CacheStorage عند فتح Dashboard.

شرط تفعيل DuckDB-WASM (في المتصفح فقط، وليس Worker): فقط إذا كان deviceMemory >= 4 و hardwareConcurrency >= 4 وليس متصفح موبايل، وإلا يُستخدم JSON Rollup الجاهز.

DuckDB يستعلم عن ملفات Parquet من B2 عبر Presigned URLs (صالحة 30 دقيقة مع تجديد تلقائي في الواجهة).

4.1. OptimisticUpdateManager (Frontend)
typescript
interface PendingMutation {
  entityId: string;
  sequence: number;
  oldValue: any;
  newValue: any;
  status: 'pending' | 'committed' | 'failed';
}

// نحتاج إلى واجهة Getter لاسترجاع القيمة الحالية
interface CurrentValueGetter {
  getCurrentValue(entityId: string): any;
}

class OptimisticUpdateManager {
  private stack = new Map<string, PendingMutation[]>();
  private sequenceCounter = 0;
  private getter: CurrentValueGetter;

  constructor(getter: CurrentValueGetter) {
    this.getter = getter;
  }

  apply(entityId: string, newValue: any): number {
    const seq = ++this.sequenceCounter;
    const oldValue = this.getter.getCurrentValue(entityId); // ✅ استخدام getter
    const mutation: PendingMutation = {
      entityId,
      sequence: seq,
      oldValue,
      newValue,
      status: 'pending'
    };
    const mutations = this.stack.get(entityId) || [];
    mutations.push(mutation);
    this.stack.set(entityId, mutations);
    this.applyToUI(entityId, newValue);
    this.applyToIndexedDB(entityId, newValue, seq);
    return seq;
  }

  rollback(entityId: string, failedSeq: number) {
    const mutations = this.stack.get(entityId) || [];
    const failedIndex = mutations.findIndex(m => m.sequence === failedSeq);
    if (failedIndex === -1) return;

    // ✅ Snapshot قبل الـ Replay لمنع Race Condition
    const mutationsSnapshot = [...mutations.slice(failedIndex + 1)];

    // 1. Rollback الفاشل فقط
    const failed = mutations[failedIndex];
    this.applyToUI(entityId, failed.oldValue);
    this.applyToIndexedDB(entityId, failed.oldValue, failedSeq);

    // 2. Replay الأحداث اللاحقة (من الـ Snapshot)
    for (const mutation of mutationsSnapshot) {
      this.applyToUI(entityId, mutation.newValue);
      this.applyToIndexedDB(entityId, mutation.newValue, mutation.sequence);
    }

    // 3. إزالة الفاشل من الـ Stack
    mutations.splice(failedIndex, 1);
  }

  commit(entityId: string, sequence: number) {
    const mutations = this.stack.get(entityId) || [];
    const idx = mutations.findIndex(m => m.sequence === sequence);
    if (idx !== -1) mutations[idx].status = 'committed';
  }

  private applyToUI(entityId: string, value: any) {
    // تنفيذ تحديث الواجهة
  }

  private applyToIndexedDB(entityId: string, value: any, sequence: number) {
    // تنفيذ تحديث IndexedDB
  }
}

// D1 Schema (Idempotency Keys)
const IDEMPOTENCY_SCHEMA = `
  CREATE TABLE IF NOT EXISTS idempotency_keys (
    key TEXT PRIMARY KEY,
    store_id TEXT NOT NULL,
    created_at INTEGER DEFAULT (unixepoch())
  );
`;

// Capture Worker
async function handleCapture(request: Request) {
  const event = await request.json();
  const { storeId, idempotency_key, client_created_at } = event;

  // 1. Idempotency Check (D1)
  const result = await env.DB.prepare(
    `INSERT OR IGNORE INTO idempotency_keys (key, store_id) VALUES (?, ?)`
  ).bind(idempotency_key, storeId).run();

  if (result.changes === 0) {
    return new Response('Duplicate event (ignored)', { status: 200 });
  }

  // 2. Server Time Canonicalization
  const serverReceivedAt = Date.now();
  const drift = serverReceivedAt - client_created_at;
  const isBackfilled = Math.abs(drift) > 5 * 60 * 1000;

  // 3. Write to D1 (مع اسم الجدول الديناميكي)
  const tableName = getTableName();
  await env.DB.prepare(`
    INSERT INTO ${tableName} (
      event_id, store_id, actor, type, entity, changes,
      client_created_at, server_received_at, is_backfilled, idempotency_key
    ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
  `).bind(
    event.event_id, storeId, JSON.stringify(event.actor), event.type,
    JSON.stringify(event.entity), JSON.stringify(event.changes),
    client_created_at, serverReceivedAt, isBackfilled ? 1 : 0, idempotency_key
  ).run();

  // 4. Update Redis last_ts
  await env.REDIS.set(`store:${storeId}:last_ts`, serverReceivedAt, { ex: 3600 });

  // 5. Send SSE pulse (if connection exists)
  await sendSSEPulse(storeId, { event_id: event.event_id, type: event.type });

  return new Response('OK', { status: 200 });
}
4.3. المزامنة المحلية (BroadcastChannel + Fallback)
typescript
class CrossTabBus {
  private channel: BroadcastChannel | null = null;
  private listeners: Set<(data: any) => void> = new Set();

  constructor(private channelName: string) {
    if ('BroadcastChannel' in window) {
      this.channel = new BroadcastChannel(channelName);
      this.channel.onmessage = (e) => this.notify(e.data);
    } else {
      // Fallback: localStorage + storage event
      window.addEventListener('storage', (e) => {
        if (e.key === this.channelName && e.newValue) {
          this.notify(JSON.parse(e.newValue));
        }
      });
    }
  }

  postMessage(data: any) {
    if (this.channel) {
      this.channel.postMessage(data);
    } else {
      localStorage.setItem(this.channelName, JSON.stringify(data));
      setTimeout(() => localStorage.removeItem(this.channelName), 100);
    }
  }

  private notify(data: any) {
    for (const listener of this.listeners) {
      listener(data);
    }
  }

  onMessage(callback: (data: any) => void) {
    this.listeners.add(callback);
  }
}
4.4. SSE Handler (Stateless Worker مع On-Demand)
typescript
// ✅ استخدام Composite Key: storeId + tabId
const activeConnections = new Map<string, ReadableStreamDefaultController>();
const MAX_CONNECTIONS_PER_STORE = 5;

async function handleSSE(request: Request, storeId: string) {
  const url = new URL(request.url);
  const tabId = url.searchParams.get('tabId') || 'default';

  // ✅ التحقق من عدد الاتصالات
  let count = 0;
  for (const key of activeConnections.keys()) {
    if (key.startsWith(`${storeId}:`)) count++;
  }
  if (count >= MAX_CONNECTIONS_PER_STORE) {
    return new Response('Too many connections', { status: 429 });
  }

  const connectionKey = `${storeId}:${tabId}`;
  const { 0: response, 1: controller } = new TransformStream();
  activeConnections.set(connectionKey, controller);

  // ✅ إغلاق تلقائي بعد 30 ثانية خمول
  const timeoutId = setTimeout(() => {
    controller.close();
    activeConnections.delete(connectionKey);
  }, 30000);

  // ✅ Keep-Alive كل 20 ثانية
  const keepAlive = setInterval(() => {
    try { controller.enqueue(`: ping\n\n`); } catch { clearInterval(keepAlive); }
  }, 20000);

  // تنظيف عند الإغلاق
  request.signal.addEventListener('abort', () => {
    clearTimeout(timeoutId);
    clearInterval(keepAlive);
    activeConnections.delete(connectionKey);
  });

  return new Response(response, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
    },
  });
}

// ✅ إرسال نبضة للاتصال المفتوح
async function sendSSEPulse(storeId: string, data: any) {
  const events: Promise<void>[] = [];
  for (const [key, controller] of activeConnections) {
    if (key.startsWith(`${storeId}:`)) {
      events.push(
        new Promise(resolve => {
          try {
            controller.enqueue(`data: ${JSON.stringify(data)}\n\n`);
          } catch {}
          resolve();
        })
      );
    }
  }
  await Promise.all(events);
}
4.5. Polling Fallback (العميل)
typescript
class AdaptivePoller {
  private backoff = 1000;
  private maxBackoff = 10000;
  private isPolling = false;

  async start(storeId: string) {
    this.isPolling = true;
    await this.poll(storeId);
  }

  stop() {
    this.isPolling = false;
  }

  private async poll(storeId: string) {
    if (!this.isPolling) return;

    if (!navigator.onLine) {
      await this.waitForOnline();
      this.backoff = 1000;
    }

    try {
      const res = await fetch(`/api/pulse?storeId=${storeId}&ts=${Date.now()}`, {
        headers: { 'If-None-Match': this.getLastETag() }
      });

      if (res.status === 304) {
        this.backoff = Math.min(this.backoff * 1.5, this.maxBackoff);
      } else if (res.ok) {
        const events = await res.json();
        this.handleEvents(events);
        this.backoff = 1000;
      } else {
        throw new Error('Server error');
      }
    } catch {
      this.backoff = Math.min(this.backoff * 2, this.maxBackoff);
      this.backoff += (Math.random() * 2000) - 1000; // Jitter
    }

    setTimeout(() => this.poll(storeId), this.backoff);
  }

  private waitForOnline(): Promise<void> {
    return new Promise(resolve => {
      if (navigator.onLine) return resolve();
      window.addEventListener('online', () => resolve(), { once: true });
    });
  }
}

// ✅ استخراج storeId من الـ Active Window
async function getStoreIdFromClient(): Promise<string> {
  const clients = await self.clients.matchAll({
    type: 'window',
    includeUncontrolled: true
  });

  for (const client of clients) {
    const url = new URL(client.url);
    const match = url.pathname.match(/\/store\/([^\/]+)/);
    if (match) return match[1];
  }
  return 'default';
}

// ✅ Pre-fetch Rollups
self.addEventListener('install', (event) => {
  event.waitUntil(
    (async () => {
      const storeId = await getStoreIdFromClient();
      const urls = [
        `https://cdn.dokany.com/b2/rollups/store_${storeId}/last_7_days.json`,
        `https://cdn.dokany.com/b2/rollups/store_${storeId}/last_30_days.json`,
      ];
      const cache = await caches.open('rollups');
      for (const url of urls) {
        try {
          const response = await fetch(url, { cache: 'force-cache' });
          if (response.ok) await cache.put(url, response);
        } catch {
          console.warn('Pre-fetch failed:', url);
        }
      }
    })()
  );
});

⚠️ تنبيه للمطور: يجب الالتزام الصارم بالقواعد التالية أثناء توليد أو كتابة كود النظام:

الـ Frontend & State:

Dynamic State Retrieval: في الـ OptimisticUpdateManager استخدم دالة getCurrentValue(entityId) جلب صريح للقيم من الـ Store وتجنب الـ Magic Numbers أو الـ Static Fallbacks.

Snapshot-Based Rollback: عند فشل حدث أوبتيمستك، خذ Snapshot صريح لمصفوفة الأحداث المعلقة قبل إعادة تطبيقها (Replay) لضمان عدم السقوط في Race Condition بين التبويبات.

Multi-Tab Orchestration: المزامنة محلياً داخل جهاز التاجر تعتمد حصراً على BroadcastChannel (مع Fallback لـ localStorage للتبويبات القديمة).

الـ Capture Worker & Cloudflare D1:

Dynamic Audit Tables: اسم جدول السجلات يُولّد ديناميكياً بناءً على تاريخ الشهر الحالي UTC بصيغة audit_logs_YYYY_MM.

Idempotency Strategy: تحقق أولاً من الـ idempotency_key بجدول D1 عبر INSERT OR IGNORE. إذا كان التغيير 0 يخرج الووركر فوراً بـ 208 Already Reported.

Batch Deletes: عند تنفيذ عمليات تنظيف لقاعدة البيانات في الـ Cron Jobs، استخدم Batched Deletes (مثلاً LIMIT 1000) لتجنب أخطاء Lock/Timeout في D1.

الـ SSE & Service Worker:

Composite Key SSE Connections: مفتاح الاتصال بـ SSE يتكون من ${storeId}:${tabId}. الحد الأقصى 5 اتصالات متزامنة لكل متجر.

Active Window Store Isolation: استخرج الـ storeId داخل الـ Service Worker ديناميكياً من نافذة العرض النشطة باستخدام self.clients.matchAll().

Memory Safety: يمنع تشغيل DuckDB-WASM داخل الـ Worker لتقليل استهلاك الـ RAM، ويُكتفى بمكتبة Parquet خفيفة في الـ Backend للدمج والتقطيع.
