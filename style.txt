🏛️ دكاني - الدستور المعماري لنظام الأنماط (CSS Architecture Blueprint)
الإصدار: 3.0 (النسخة المعمارية القطعية النهائية - The Ultimate Production-Ready Edition)
الهوية: نظام إدارة الأنماط المعزول بالمجالات (Domain-Isolated CSS Architecture) يعمل على حافة Cloudflare، مع حقن صفري زمنياً (Zero-Runtime Injection)، وعزل تام بين بيئات التطبيق، ونظام توريث ذكي، واستراتيجية اختبارية متكاملة.

📜 الديباجة: فلسفة "الأنماط كمواطن من الدرجة الأولى"
الأنماط ليست مجرد أوراق أنيقة تزين الواجهة؛ بل هي جزء أساسي من دورة حياة التطبيق، يجب أن تُعامل كأي موديول آخر:

لها دورة حياة كاملة (جلب → تحويل → توجيه → تطبيق).

لها طبقات معزولة (Core، Shared، Domain Engines).

لها بوابات دخول صارمة (Index Gates) لمنع التسرب والتشابك.

لها نظام توريث ذكي مع حماية ضد التوريث الدائري.

لها استراتيجية تخزين مزدوجة (KV للقراءة السريعة + D1 للمصدر الأساسي).

لها أداء صفري على العميل (Zero-Runtime) عبر الحقن المباشر في تدفق HTML من الحافة.

✨ المبادئ الحاكمة (9 مبادئ)
المبدأ	الوصف
العزل المطلق للمجال (Strict Domain Isolation)	كل بيئة (Storefront، Builder، Dashboard، Mini-App) لها مجلد مستقل تماماً. لا يُسمح بتسرب أي كلاس أو نمط بين البيئات.
الحقن الصفري زمنياً (Zero-Runtime Injection)	الأنماط تُحقن في تدفق HTML من الحافة (Edge/Server) قبل وصولها للمتصفح. لا يوجد أي انتظار لـ JavaScript أو IndexedDB أثناء التصيير الأولي.
الفصل بين الجلب والتحويل والتطبيق	الطبقات منفصلة: shared/theme-provider (جلب)، shared/css-vars-generator (تحويل)، وكل Domain Engine (تطبيق).
التوجيه بالسياق (Context-Aware Routing)	كل بيئة لها Domain Engine خاص بها يقرر كيفية دمج الـ Core مع الـ CSS الخاص بالبيئة.
الاعتماد على البوابات (Index Gates)	لا يمكن لأي ملف خارج الموديول استيراد ملف داخلي مباشرة. كل التفاعل يتم عبر البوابات (styles/index.ts أو styles/[domain]/index.ts).
نظام التوريث الذكي (Theme Inheritance)	دعم توريث الثيمات مع دمج عميق (Deep Merge) وحماية ضد التوريث الدائري (Circular Inheritance Protection).
استراتيجية التخزين المزدوجة (KV + D1)	استخدام Edge KV للقراءة فائقة السرعة (0ms)، مع D1 كمصدر أساسي للبيانات ونسخ احتياطي.
إبطال الكاش الفوري (Cache Invalidation)	آلية واضحة لإبطال الكاش عند تحديث الثيم، لضمان ظهور التغييرات فوراً.
استراتيجية اختبارية شاملة (Testing Strategy)	اختبارات وحدة، اختبارات لقطات، اختبارات تكامل، واختبارات عقود.

1.2 واجهة الـ Domain Engine
typescript
/**
 * 🎼 الـ Domain Engine (يجمع بين الـ Adapter والـ Orchestrator)
 * كل بيئة (Storefront، Builder، Admin، Mini-App) لها Domain Engine خاص بها
 */
export interface DomainEngine<T = Theme, C = unknown> {
  /**
   * اسم المحرك (للتصحيح)
   */
  readonly name: string;

  /**
   * إصدار المحرك
   */
  readonly version: string;

  /**
   * تحويل الثيم إلى كائن CSS Variables (خاص بالبيئة)
   */
  transform(theme: T, context: C): Record<string, string>;

  /**
   * جلب الثيم المناسب للسياق
   */
  getTheme(context: C): Promise<T> | T;

  /**
   * توليد كود CSS كامل جاهز للحقن في <head>
   */
  render(context: C): Promise<string>;

  /**
   * تحديث الثيم (للـ Live Preview أو التحديثات)
   */
  updateTheme(identifier: string, newTheme: Partial<T>): Promise<void>;
}
🔄 الباب الثاني: تدفق البيانات المعماري
2.1 استراتيجية التخزين (KV vs D1)
المصدر	الاستخدام	السرعة	التكلفة
Edge KV	قراءة الـ Theme Snapshots للـ Storefront	0ms (فورية)	مجاناً (ضمن 1GB)
D1	المصدر الأساسي للثيمات (مع جدول store_themes)	~50ms	مجاناً (ضمن 5GB)
IndexedDB	Cache احتياطي للتصفح غير المتصل (Offline PWA)	غير متزامن	مجاناً
استراتيجية القراءة:

الـ Storefront: يقرأ من Edge KV أولاً (0ms)، فإن لم يجد يقرأ من D1 ويُخزّن في KV.

الـ Builder / Dashboard: يقرأ من D1 مباشرة (لأن الثيم قد يكون قيد التحرير).

الـ Mini-App: يقرأ من Edge KV (للسرعة) مع مزامنة مع ثيم تليجرام.

استراتيجية الكتابة:

الكتابة تتم في D1 أولاً (المصدر الأساسي).

ثم يتم تحديث Edge KV (للقراءة السريعة).

ثم يتم إرسال إشارة Purge إلى الـ Edge Cache.

3.1 الـ Base Domain Engine (shared/base-domain-engine.ts)
الدور: كلاس أساسي للتوجيه، يُورث منه كل Domain Engines.

الميزات المشتركة:

منطق جلب الثيم (باستخدام theme-provider مع استراتيجية KV/D1).

منطق تحويل الثيم (باستخدام css-vars-generator).

منطق تطبيق التوريث (باستخدام theme-inheritance).

منطق تخزين الثيم في الـ Cache (إن أمكن).

دوال مساعدة للتصحيح (Logging، Metrics).

typescript
// مثال على هيكل BaseDomainEngine
export abstract class BaseDomainEngine<T extends Theme, C> implements DomainEngine<T, C> {
  abstract readonly name: string;
  abstract readonly version: string;

  // دوال مشتركة (جلب، تحويل، تطبيق)
  async getTheme(context: C): Promise<T> {
    // استخدام theme-provider مع استراتيجية KV/D1
  }

  abstract transform(theme: T, context: C): Record<string, string>;

  async render(context: C): Promise<string> {
    const theme = await this.getTheme(context);
    const vars = this.transform(theme, context);
    return generateCSSVariables(vars);
  }

  abstract updateTheme(identifier: string, newTheme: Partial<T>): Promise<void>;
}
3.2 نظام التوريث (shared/theme-inheritance.ts)
الدور: دمج الثيم الأب مع الـ overrides الخاصة بالثيم الفرعي.

آلية العمل:

يستخدم الدمج العميق (Deep Merge) لدمج الـ overrides مع الثيم الأب.

يدعم التوريث المتعدد المستويات (جد → أب → ابن).

يحتوي على حماية ضد التوريث الدائري (Circular Inheritance Protection).

استراتيجية الـ Deep Merge:

دمج الكائنات المتداخلة (Nested Objects) بدلاً من استبدالها.

الحفاظ على القيم غير المغطاة من الثيم الأب.

تطبيق الـ overrides فقط على الحقول المحددة.

حماية التوريث الدائري:

تتبع سلسلة التوريث (Parent Chain) أثناء الدمج.

إذا تم اكتشاف دورة (مثل: A ← B ← A)، يتم إيقاف الدمج وإرجاع خطأ.

أقصى عمق مسموح: 10 مستويات (لحماية من التكرار اللانهائي).

3.3 الـ Theme Provider (shared/theme-provider.ts)
الدور: جلب الثيم من المصدر المناسب حسب البيئة مع دعم إبطال الكاش.

آلية العمل:

الـ Storefront: يقرأ من Edge KV أولاً (0ms)، فإن لم يجد يقرأ من D1.

الـ Builder / Dashboard: يقرأ من D1 مباشرة (لأن الثيم قد يكون قيد التحرير).

الـ Mini-App: يقرأ من Edge KV مع مزامنة مع ثيم تليجرام.

آلية إبطال الكاش (Cache Invalidation):

عند تحديث الثيم، يتم تحديث حقل updatedAt في D1.

يتم حذف المفتاح من Edge KV فوراً.

يتم إرسال إشارة Purge إلى الـ Edge Cache عبر Cloudflare API.

theme-provider يتحقق من updatedAt قبل إرجاع الثيم من الكاش.

3.4 الـ CSS Variables Generator (shared/css-vars-generator.ts)
الدور: تحويل كائن Theme إلى CSS Variables String جاهز للحقن.

آلية العمل:

يستقبل Theme (كائن) ويُخرج نصاً مثل:

css
:root {
  --primary-main: #6366f1;
  --primary-light: #818cf8;
  --text-primary: #111827;
  /* ... */
}
يدعم تحويل الـ Nesting (مثل colors.primary.main → --colors-primary-main).

يدعم تحويل الأرقام إلى وحدات (مثل spacing.unit: 4 → --spacing-unit: 4px).

هو Pure Function، مما يسهل اختباره بشكل كبير.
